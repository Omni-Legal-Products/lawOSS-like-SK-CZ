Architecture Decision Record — návrh

ADR 0005 — Štruktúra repozitárov

Koordináciu oddelene od kódu. Nie vo vetvách jedného repa.

Dátum: 2026-08-06 Stav: 📝 návrh — na stredajší call Navrhol: MČ

1Kontext

Toto repo je výhradne koordinačné — nápady, rozhodnutia, rešerše, projektové riadenie. Neobsahuje kód produktu a nemá ho obsahovať.

Zvažovalo sa riešenie v tomto repe cez druhú vetvu: main na koordináciu, samostatná vetva na appku. Cieľ za tým je správny — jedno miesto, jeden odkaz, nízka réžia. Nižšie je návrh, ako ho dosiahnuť bez nevýhod vetvy.

3Prečo nie vetva v tomto repe

DôvodVysvetlenie
Fork potrebuje vlastné repoUpstream sync vyžaduje upstream remote. Histórie tohto repa a LegalWorku sú nesúvisiace — spájali by sa cez --allow-unrelated-histories, hack, ktorý sa pri každom ďalšom pulle rozsype. Zabilo by to presne tú vlastnosť, kvôli ktorej sme LegalWork zvolili.
Vetvy sa majú zlievaťVetva s úplne iným stromom, ktorá sa nikdy nemergne do main, nie je vetva — je to druhé repo schované v prvom. git merge main by miešal dokumentáciu do kódu.
LicenciaKód odvodený od LegalWorku musí niesť jeho MIT licenciu a atribúciu. Koordinačné repo je iné dielo. V jednom repe by bolo nejednoznačné, čo je pod čím — zbytočné riziko pre advokátov publikujúcich open source.
Issues, PR a releasesJeden tracker pre „diskusia o roadmape“ aj „appka padá pri OCR“. Appka bude potrebovať verzované buildy, koordinačné repo nie.
Skúsenosť prispievateľaKolega, ktorý chce appku vyskúšať, by si klonoval zápisy zo stretnutí.

Jeden argument, ktorý NEPLATÍ

Automatizácie by problém nespôsobili — update-readme.yml aj telegram-notify.yml majú branches: [main], takže na inej vetve sa nespustia. (Overené 2026-08-06.)

4Ako splniť pôvodný cieľ „jedno miesto“

GitHub organizácia. Dá jednu landing stránku, jeden názov, spoločné členstvo a práva naprieč repami — presne to, čo vetva sľubovala, ale bez jej nevýhod.

  • Názov v súlade so značkou: LAWOSS. (Dostupnosť lawoss na GitHube neoverená — treba skontrolovať.)
  • Presun existujúceho repa je bezpečný — GitHub drží presmerovanie zo starých URL. Pozor len na GitHub Pages: URL sa zmení.
  • Vhodná príležitosť presunúť pod organizáciu aj judikaty-mcp, ktorý je dnes private a bez licencie — a tým blokuje komunitnú časť projektu.

5Dôsledky

  • Toto repo sa nemení — zostáva koordinačné.
  • Vzniká jedno nové repo (balík vrstvy A), zatiaľ bez forku.
  • Treba rozhodnúť, či zakladáme organizáciu hneď, alebo až keď bude kód.
  • Do každého README patrí odkaz na to druhé repo.

Nič z toho ešte nie je vytvorené. Založenie organizácie, forku aj nového repa čaká na odsúhlasenie tímom.
